# Monster Forge: Build, Merge & Battle

เกมจัดทีมมอนสเตอร์ผ่านไฟล์ JavaScript สำหรับเวิร์กช็อป Git & GitHub ใช้ HTML/CSS/JavaScript ธรรมดา ไม่ต้องติดตั้ง dependency ไม่มี backend และไม่เรียกบริการภายนอก

## เปิดใช้งาน

ดับเบิลคลิก `game/index.html` แล้วกด **เริ่มต่อสู้** ไม่ต้องใช้ npm หรือเปิด server แก้ไฟล์แล้วบันทึกและรีเฟรช (F5) หากยังเห็นข้อมูลเก่าให้กด Ctrl+Shift+R

หน้าเว็บไม่มีส่วนเลือกหรือดูรายชื่อมอนสเตอร์ ทีมและลำดับการลงสนามกำหนดจากไฟล์ของนักเรียนเท่านั้น มอนสเตอร์แต่ละตัวจะถูกเปิดเผยตอนลงสนาม

## แก้ทีมมอนสเตอร์

- คน A แก้ `student-a/monsters.js` (3 ตัว: `a1`, `a2`, `a3`) และวางรูปใน `student-a/images/`
- คน B แก้ `student-b/monsters.js` (3 ตัว: `b1`, `b2`, `b3`) และวางรูปใน `student-b/images/`

ทุกบรรทัดในไฟล์มีคอมเมนต์อธิบายไว้ แก้ได้ทั้ง `name`, `description`, `image`, `element`, `skill`, `trait` และ `stats` แต่ห้ามแก้ `id` และห้ามลบเครื่องหมาย `" , { } [ ]`

## การต่อสู้

1. ตัวที่ id ลงท้ายด้วย **1** ของทั้งสองทีมลงสนามก่อน ตัวที่ speed สูงกว่าได้ตีก่อน ป้ายสีน้ำเงินด้านบนการ์ดบอกว่าตอนนี้เป็นตัวที่เท่าไหร่
2. ผลัดกันลงมือคนละเทิร์น เมื่อตัวใดหมดแรง เกมจะหยุดรอ กด **สู้ต่อ** เพื่อส่งตัวลำดับถัดไปของทีมนั้นลงสนาม
3. ตัวที่ชนะยังอยู่ในสนามต่อพร้อม HP ที่เหลือ เมื่อมีตัวใหม่ลงสนามจะเทียบ speed ใหม่ว่าใครได้ตีก่อน
4. ทีมที่หมดแรงครบ 3 ตัวก่อนเป็นฝ่ายแพ้ ถ้าหมดพร้อมกันถือว่าเสมอ
5. หลังเทิร์นที่ 60 ทุกตัวจะเริ่มเหนื่อยล้าและตีแรงขึ้นเรื่อยๆ เพื่อไม่ให้เกมยืดเยื้อ ถ้าครบ 300 เทิร์น ทีมที่เหลือตัวหรือ HP มากกว่าชนะ
6. ปุ่ม **ดูผลทันที** จะข้ามไปจนจบเฉพาะคู่ที่กำลังสู้อยู่ แล้วเปลี่ยนเป็นปุ่ม **สู้ต่อ** เมื่อจบทั้งเกมจะขึ้นปุ่ม **ต่อสู้อีกรอบ**
7. หลอดเลือดแสดงแถบสีแดงเมื่อโดนตี และแถบสีเขียวสว่างเมื่อฟื้น HP พร้อมตัวเลข -/+ ลอยขึ้นมา คริติคอลตัวเลขใหญ่ขึ้น หลบได้จะขึ้นคำว่า หลบ! และตอนใช้สกิลจะมีป้ายชื่อสกิลตัวใหญ่ขึ้นด้านบนการ์ด

## ธาตุ

`element` เลือกได้ 7 ธาตุ จะเขียนเป็นชื่ออังกฤษหรือชื่อไทยก็ได้

| ค่า | ธาตุ | สีป้าย | ชนะ | บัพทีม |
| --- | --- | --- | --- | --- |
| `wind` | ลม | เขียวอ่อน | สายฟ้า | ทุกการโจมตีแรงขึ้น 12% |
| `rock` | หิน | น้ำตาล-ส้ม | ลม | ทุกการโจมตีได้โล่ 15% ของดาเมจที่ทำได้ |
| `plant` | พืช | เขียวเข้ม | หิน | ทุกการโจมตีฟื้น HP 18% ของดาเมจที่ทำได้ |
| `fire` | ไฟ | แดง-ส้ม | พืช | ทุกการโจมตีเผาซ้ำอีก 12% ของดาเมจเดิม |
| `water` | น้ำ | น้ำเงิน-ฟ้า | ไฟ | รอดตาย 1 ครั้งต่อตัว แล้วฟื้นเป็น 10% HP สูงสุด |
| `ice` | น้ำแข็ง | ฟ้าอ่อน | น้ำ | ตีโดนแล้วลด SPD ศัตรู 4 (สูงสุด 16) ศัตรูที่ช้าลงจะตีพลาดง่ายขึ้น |
| `lightning` | สายฟ้า | ม่วง | น้ำแข็ง | ตีโดนแล้วลด DEF ศัตรู 3 (สูงสุด 12) ลดจนติดลบได้ = โดนแรงขึ้น |

ลำดับการชนะ (ซ้ายแพ้ขวา): ลม ← หิน ← พืช ← ไฟ ← น้ำ ← น้ำแข็ง ← สายฟ้า ← ลม ธาตุจะชนะหรือแพ้กันเฉพาะคู่ที่อยู่ติดกันในลำดับนี้เท่านั้น เช่น พืชกับลมไม่ได้แพ้หรือชนะกัน และมีผล**เฉพาะมอนสเตอร์ 2 ตัวที่กำลังสู้กันอยู่** ธาตุในทีมเดียวกันไม่ข่มกัน

- ตีธาตุที่เราชนะ ดาเมจ ×1.25
- ตีธาตุที่เราแพ้ ดาเมจ ×0.75 และ**บัพทีมทุกอย่างไม่ทำงาน**ในการโจมตีนั้น (ยกเว้นบัพน้ำ เพราะเป็นบัพของฝ่ายที่ถูกตี)

### บัพทีม

บัพคำนวณจากธาตุของมอนสเตอร์ทั้ง 3 ตัวในทีม และส่งผลกับทุกตัวในทีมตลอดเกม

| ธาตุในทีม | จำนวนบัพ | ความแรงบัพ |
| --- | --- | --- |
| ธาตุเดียวกันทั้ง 3 ตัว | 1 | ×3.5 |
| มี 2 ธาตุ (มีตัวซ้ำ 1 ตัว) | 2 | ×1.4 |
| 3 ธาตุไม่ซ้ำกัน | 3 | ×1 |

ตัวคูณความแรงมีไว้ให้ทีมที่ได้บัพน้อยยังสู้ได้ จากการจำลองแบบสุ่ม ทีม 3 บัพยังได้เปรียบอยู่บ้าง (ชนะประมาณ 54%) ส่วนทีม 1 และ 2 บัพชนะประมาณ 42–44%

## สเตตัส (รวมไม่เกิน 100 แต้ม)

| ค่า | เพดาน | ผล |
| --- | --- | --- |
| hp | 50 | HP สูงสุด = 110 + hp × 3.25 |
| attack | 40 | ดาเมจพื้นฐาน = 22 + attack × 0.52 |
| defense | 40 | ดาเมจที่โดน × 42 / (42 + defense) |
| speed | 40 | ได้ตีก่อนตอนลงสนาม หลบ +0.2% และโอกาสโจมตีซ้ำ +0.45% ต่อแต้ม |
| critical | 25 | โอกาสคริ 1.4% ต่อแต้ม ดาเมจ 2 เท่า |
| lifesteal | 20 | ฟื้น HP 1.85% ของดาเมจที่ทำได้ต่อแต้ม |
| evasion | 20 | หลบ 1.25% ต่อแต้ม (หลบรวมทุกแหล่งไม่เกิน 45%) |
| armorPierce | 30 | มองข้าม DEF ศัตรู 3% และดาเมจ +0.6% ต่อแต้ม |

ค่าที่เกินเพดานจะถูกลดให้เท่าเพดาน ถ้ารวมแล้วยังเกิน 100 จะลดทุกค่าตามสัดส่วน หน้าเว็บจะแสดงคำเตือนสีส้มโดยไม่แก้ไฟล์ต้นฉบับ ส่วนค่าที่ไม่ใช่ตัวเลข ธาตุ/สกิล/ติดตัวที่สะกดผิด หรือ id ไม่ครบ 1-2-3 จะแสดงข้อผิดพลาดสีแดงและยังเริ่มต่อสู้ไม่ได้

## สกิล (ทำงานทุก 3 เทิร์นของตัวเอง)

| skill | ผล |
| --- | --- |
| strike | โจมตีแรง 1.95 เท่า |
| critStrike | โจมตีแรง 1.25 เท่า และโอกาสคริติคอล +50% (เข้ากับสายคริและ hardCrit) |
| poison | โจมตีปกติ และติดพิษ 3 เทิร์น เทิร์นละ 6% HP สูงสุด (พิษทะลุโล่) |

## การปรับสมดุล

ตัวเลขทั้งหมดอยู่ใน `rules` ด้านบนของ `game/js/data.js` ที่เดียว ทั้งระบบต่อสู้และหน้ากติกาในเว็บจะอ่านค่าจากตรงนั้น ค่าที่ใช้อยู่ตอนนี้ได้มาจากการจำลองแบบสุ่มหลายหมื่นแมตช์ โดยตรวจว่า:

- สายสเตตัสหลัก 11 แบบ (สายถึก สายคริ สายหลบ สายดูดเลือด สายเจาะเกราะ ฯลฯ) ชนะกันเองอยู่ในช่วงประมาณ 39–63%
- สกิลทั้ง 5 ชนะอยู่ในช่วง 48–51% ติดตัว none/thorns/regeneration/berserk อยู่ในช่วง 49–53% ส่วน hardCrit เป็นติดตัวเฉพาะสายคริ (ใส่ตัวทั่วไปชนะประมาณ 43% ใส่สายคริชนะประมาณ 58%)
- ธาตุทั้ง 7 ชนะอยู่ในช่วง 48–52%
- เกมยาวเฉลี่ยประมาณ 40 เทิร์น

## ใส่รูปของตัวเอง

1. นำไฟล์ PNG, JPG, SVG หรือ WebP ไปใส่ใน `images/` ของโฟลเดอร์ตัวเอง
2. ตั้งชื่อไฟล์เป็นตัวอักษรไทย/อังกฤษ ตัวเลข ขีดกลาง ขีดล่าง หรือช่องว่าง
3. แก้เป็น `image: "images/ชื่อรูป.png",`
4. ถ้ารูปหายหรือ path ผิด จะแสดงรูปสำรองแทน

## ไฟล์ที่ผู้เรียนไม่ต้องแก้

ทุกไฟล์ในโฟลเดอร์ `game/` ผู้เรียนแก้เฉพาะ `student-a/` หรือ `student-b/` ของตัวเอง ไฟล์รอบบอสเดิมถูกย้ายไปเก็บไว้ที่ `game/_dev/legacy/`

## เตรียมงานสำหรับผู้จัด

1. สร้าง GitHub repository ให้ root มีโฟลเดอร์ `student-a/`, `student-b/`, `game/` และ `README.md` แล้ว push เวอร์ชันเริ่มต้น
2. เตรียม branch `develop` และให้ทั้งคู่มีสิทธิ์ push branch / เปิด PR / merge ตามรูปแบบห้องเรียน
3. ให้ผู้เรียนติดตั้ง Git และ VS Code พร้อมตั้งค่า Git name/email และเข้าสู่ระบบ GitHub ไว้ก่อน
4. ให้ทั้งคู่ clone repository เดียวกัน เช่น `git clone <URL ของ repository>` แล้วเปิดโฟลเดอร์ที่ clone ใน VS Code ใช้ Terminal ของ VS Code รันคำสั่งด้านล่าง
5. เปิด `game/index.html` ตรวจว่าทั้งสองทีมไม่มีข้อผิดพลาดสีแดงและกดเริ่มต่อสู้ได้

คำสั่งด้านล่างใช้จาก root ของ repository

## รอบ 1 — สร้างมอนสเตอร์คนละไฟล์

ทั้งสองคนเริ่มจาก:

```bash
git switch develop
git pull --ff-only origin develop
```

คน A:

```bash
git switch -c feature/monster-a
# แก้ student-a/monsters.js บันทึก แล้วเปิด game/index.html ตรวจแต้ม
git add student-a/
git commit -m "Create monster A"
git push -u origin feature/monster-a
```

คน B ทำเช่นเดียวกัน แต่ใช้ `feature/monster-b`, โฟลเดอร์ `student-b/` และข้อความ commit ของตัวเอง

บน GitHub เลือก **Compare & pull request** ตั้ง **base: develop** และ **compare: feature/monster-a** หรือ `feature/monster-b` ตรวจ Files changed ให้มีเฉพาะไฟล์ที่ตั้งใจแก้ จากนั้น **Create pull request** ให้เพื่อน review แล้ว **Merge pull request** และยืนยันการ merge

เมื่อ merge ทั้งสอง PR แล้ว ทุกคนรัน:

```bash
git switch develop
git pull --ff-only origin develop
```

เปิด `game/index.html` แล้วกดเริ่มต่อสู้ การแก้คนละโฟลเดอร์ช่วยให้รอบนี้ไม่มี Merge Conflict

## รอบ 2 — (พักไว้)

รอบบอสร่วมกันแบบเดิมใช้กับระบบต่อสู้ทีมไม่ได้ ไฟล์ `boss.js` จึงถูกย้ายไปเก็บที่ `game/_dev/legacy/` ถ้าจะฝึกแก้ Merge Conflict อาจให้ทั้งคู่แก้บรรทัดเดียวกันในไฟล์ของทีมใดทีมหนึ่งแทน

## ตรวจสอบโปรเจกต์

ผู้ใช้เว็บไม่ต้องมี Node.js ผู้พัฒนาที่มี Node.js สามารถรันชุดทดสอบตรรกะโดยไม่ติดตั้งแพ็กเกจ:

```bash
cd game
node --test tests/core.test.cjs
```

ทดสอบการ cap แต้มและงบรวม ข้อมูลผิด การเปิดบอส ลำดับโจมตี การหลบ ความเสียหาย สกิล ติดตัว คริติคอล ดูดเลือด เจาะเกราะ โล่ พิษ การชนะ การเสมอ ขีดจำกัดตา และการไม่แก้ข้อมูลต้นฉบับ ส่วนการเปิดไฟล์จริง ปุ่ม ภาพ และหน้าจอมือถือให้ตรวจในเบราว์เซอร์ด้วย

ผลการตรวจสอบที่ทำจริงและข้อจำกัดอยู่ใน [tests/TESTING.md](tests/TESTING.md)

ถ้าหน้าเว็บไม่แสดงหลังแก้ไฟล์ ให้เปิด Developer Tools (F12) > Console ตรวจข้อความ SyntaxError มักเกิดจากลืมเครื่องหมายคำพูด จุลภาค หรือวงเล็บ หากแต้มผิดให้ดูข้อความสีแดงในรายการมอนสเตอร์
